# Project Instructions

## Repository Rules

### Project Overview

AWS Base Terraform Infrastructure — Terraform baseline for AWS accounts covering security, IAM, cost management, logging, and monitoring. Features are toggled via `terraform.tfvars`.

### Architecture

Four Terraform stacks:

| Stack            | Path                          | Purpose                                  |
| ---------------- | ----------------------------- | ---------------------------------------- |
| base             | `terraform/base/`             | Core security, IAM, cost controls        |
| management/audit | `terraform/management/audit/` | Organization-level security monitoring   |
| management/root  | `terraform/management/root/`  | Root account governance, SCPs, OIDC      |
| monitor          | `terraform/monitor/`          | CloudWatch metrics, logs, events, Athena |

Reusable modules live in `modules/aws/`. Lambda/Node.js functions in `lambda/` and `nodejs/`.

### Generated Files — Do Not Edit

The following directories are generated by `apm install` and will be overwritten:

- `.agents/`, `.cursor/`, `.claude/`, `.kiro/`, `.vscode/`
- `apm_modules/`

To modify agent instructions or skills, edit the source at `.apm/packages/<name>/` then run `apm install --update`.

### Build and Validation

Independent groups — run in any order. Within each group, execute sequentially.

**Terraform** (run from repo root):

```bash
terraform fmt -check -recursive
terraform validate
tflint --recursive
trivy config .
```

**Shell scripts**:

```bash
shellcheck **/*.sh
shfmt -d **/*.sh
```

**Tests**:

```bash
bats test/bats/
```

### CI/CD

- CI: Reusable workflows from `y-miyazaki/config` repo (Terraform plan, lint, trivy scan)
- CD: Environment-specific deploy workflows (dev/qa/stg/prd)
- Environments: dev, qa, stg, prd — each has its own `.tfvars` and `.tfbackend`
- Create PRs against `develop` branch. Only hotfixes target `main`.

### Terraform Conventions

- **Naming**: All snake_case (resources, variables, outputs, files)
- **Tags**: `merge(local.tags, { Name = "..." })` pattern
- **IAM policies**: `jsonencode()` or `aws_iam_policy_document` — no inline heredoc JSON
- **Key ordering**: Alphabetical within blocks
- **for_each over count**: Always prefer `for_each`; count only for enable/disable flags
- **Providers**: Version ranges `>= lower, < upper`
- **Secrets**: Never in code — use SSM Parameter Store or Secrets Manager
- **File naming**: `main_<scope>_<feature>.tf` (e.g., `main_regional_guardduty.tf`)
- **Notifications**: Follow SNS → Lambda → Slack pattern when adding alerts

### File Structure Patterns

- `terraform/<stack>/variables.tf` — all input variables
- `terraform/<stack>/locals.tf` — local values and tag definitions
- `terraform/<stack>/main_provider.tf` — provider configuration
- `terraform/<stack>/main_common_data.tf` — shared data sources
- `terraform/<stack>/terraform.example.tfvars` — reference configuration

### Temporary Artifacts

Write to `tmp/`.

### Documentation Editing

When structure, modules, or features change, update related `README.md` and `docs/` accordingly.

## Token Optimization

### Context Exclusions

- Lock files: `*.lock`, `*.lock.*`, `go.sum`
- Dependencies: `node_modules/`, `apm_modules/`, `.terraform/`
- Build artifacts: `lambda/outputs/`, `nodejs/` build outputs
- Temporary: `tmp/`, `env/common/tmp/`

### When to Read Reports

Only read `docs/report/` files when explicitly asked or when comparison/research context is needed.

## Security Guidelines

- Secrets MUST NOT appear in source code, logs, or test data.
- No destructive operations as defaults in command examples.
