# Naming & Documentation (N)

**N-01 (SHOULD): Module header documents purpose/overview**

Check: Do module files have descriptive headers?
Why: Missing module description and no header comments make usage unclear, slow onboarding, and create maintenance difficulties
Fix: Add header comment at file beginning (purpose, overview, usage example)

**N-02 (SHOULD): Documentation stays in sync with interface changes**

Check: When inputs, outputs or behavior change, are the related README/docs and example configuration (`terraform.example.tfvars`, usage snippets) updated, except content generated by a documentation tool?
Why: Stale docs and examples cause misconfiguration and hide new options from users
Fix: Update the hand-written docs and examples in the same change; leave generated sections to the generator
